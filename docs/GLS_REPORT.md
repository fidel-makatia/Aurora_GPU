# Gate-level simulation report

All of Aurora's synthesized netlists are functionally verified at gate level.
Simulator: Cadence Xcelium 24.03, zero-delay functional gate models generated
from the ASAP7 liberty function attributes (151 cells), with defined power-on
state (`AURORA_GLS_INIT0`). Every test is self-checking; a pass requires
correct computed results, not merely completion.

## Results

| Netlist under test | Test | Verdict | Simulated time | Wall clock |
|---|---|---|---|---|
| IO hub (RV32 CPU + HBM controller + command fabric, 771k cells, boundary-preserved) | Firmware bring-up: load over Wishbone debug port → `cpu_en` release → gate CPU boots, uploads kernel to 16 SMs, launches, verifies on-die | **PASS** (`FW_RESULT 600d0000`) | 111.0 µs | 2 min |
| SM core v2 (2.1M cells × 16 instances ≈ 34M gate instances) | Full-system kernel execution and result check | **PASS** | 132.5 µs | 36 min |
| RV32 core (standalone, from the boundary-preserved netlist) | Program with ALU, branches, loads/stores; memory-image check | **PASS** | 3 µs | 22 s |

The hub test exercises the true silicon bring-up sequence — firmware cannot
be back-doored into synthesized flops, so it is loaded through the external
debug port exactly as a tester would.

## Defects found by GLS (all invisible to RTL simulation; all fixed)

1. **Dual register banks from a two-writer array.** `bootram` was written
   from two always blocks (firmware-load port and CPU byte port). Synthesis
   legally inferred two complete 131k-flop arrays with shorted outputs;
   every written 1 resolved to X. RTL simulation, which keeps a single
   array, can never exhibit this. Fix: a single write process with explicit
   port priority.
2. **Unreset D2D transmit data.** `d2d_tx.tx_d` was excluded from the reset
   clause, driving X into the hub until a first transmission. The RTL
   receiver masks this (data sampled only under valid); synthesized logic
   clouds do not. Fix: reset the data path in both link directions.
3. **Undefined power-on state in behavioral memories** (SRAM macro store,
   HBM PHY store) propagates through gate-level AOI structures where RTL
   mux semantics would contain it. Fix: define-gated zero initialization
   for gate-level runs, representing silicon's defined-but-arbitrary
   power-on state.

A latent v1 defect (single-warp read-after-write hazard) had been found
earlier by the same discipline during the v2 register-file redesign.

## Method notes

- Boundary-preserved synthesis (`auto_ungroup none`) is required for
  debuggable gate netlists; flattened netlists rename every internal net.
  Submodules extracted from a *boundary-optimized* hierarchical netlist are
  not standalone-simulatable.
- Debug flow that converged: full-scope VCD dump → permanent-X census →
  first-X-onset census → structural driver-cone trace against the netlist
  connectivity graph. Guided single-signal probing did not scale.
- Reproduction: `gls/` recipes on the build host; models generated by
  `gls/gen_func_models.py` from the liberty files.
